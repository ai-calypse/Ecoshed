# Energy-first placement on Alibaba trace-derived workloads

**The active default has moved to independent raw-archive processing.**
`python -m ENERGY_Study.run` and `python -m ENERGY_Study.verify` now delegate to
[RAW_Alibaba](../RAW_Alibaba/README.md), using the uploaded archive and no Yaksh
cleaned inputs. Read [the current raw-data results](../RAW_Alibaba/REPORT.md).
The prepared-sample description and results below are historical; they are
preserved and are not relabeled as freshly processed raw-data experiments.

**All active project experiments use Alibaba data.** The default runner rejects
altered/unverified trace inputs and provides no synthetic fallback. It preserves
recorded requests, arrivals, group multiplicity and the trace-derived mean-runtime
model. The original policies and 36-case comparison remain unchanged.

```sh
python -m ENERGY_Study.run
python -m ENERGY_Study.verify
```

Run from repository root with Python 3.10+; no third-party dependencies.
The full grid is **36 runs: three Alibaba sample sizes, four policies and three
SPECpower curves**. Each curve gets the same 12 combinations independently.
Each run creates a fresh engine and loads one curve; curves are never blended.

The four policies are original CPU-oriented LR-MMT, original weighted-memory
LR-MMT, and the energy-first CPU/memory pair. All use the same LR/MMT controller,
hosts, FIFO admission, completion rules and migration/sleep assumptions.
Energy-first placement lets balance break power ties; it cannot guarantee lower
full-run energy. See [ALIBABA_REPORT.md](ALIBABA_REPORT.md) for actual outcomes.

## Data provenance

Current inputs are **prepared Alibaba v2017 trace rows in `YAKSH_Task/data/`**,
not newly downloaded raw CSVs. The 250/1,000/4,000-group samples represent
40,381/160,813/638,647 independently replayed instances on the fixed 64-host pool.
Input/config hashes must match the preparation manifest, and source-row identifiers
must be present. No replacement jobs, altered resource mix or invented arrivals
are generated by this runner.

The raw archive is absent locally and a direct download attempt could not connect
to Alibaba's server here. Each result records `fresh_raw_archive_replay: false`,
`synthetic_workload: false`, preparation-package identity and input hashes.
Prepared rows must not be described as independently processing the raw archive.

## Results and commands

- [ALIBABA_REPORT.md](ALIBABA_REPORT.md): active Alibaba-derived comparison.
- [alibaba_reports/comparison.csv](alibaba_reports/comparison.csv): full results.
- [alibaba_reports/validation.json](alibaba_reports/validation.json): provenance,
  complete per-curve matrix and work-conservation validation.
- [alibaba_config.json](alibaba_config.json): common assumptions.

```sh
# Small real-data smoke run: four policies, one Alibaba sample, one curve
python -m ENERGY_Study.run --sizes 250 --curves hpe_dl360_gen9 --output ENERGY_Study/alibaba_smoke
python -m ENERGY_Study.verify --reports ENERGY_Study/alibaba_smoke --allow-partial

# Constructed inputs in these tests are code fixtures, not benchmark evidence
python -m unittest discover -s ENERGY_Study/tests -v
```

Use `--details` for instance, migration and host-sample CSVs, or `--output` for a
separate destination. Compact per-run summaries are always saved. Verification
can combine disjoint partitions with `--source`, writing aggregates to `--reports`.
The full matrix is required unless `--allow-partial` is explicitly used for smoke
validation. This single fixed benchmark supplies no independent-window confidence
intervals or production electricity measurements.

Instrumentation adds event-integrated energy components, fragmentation,
stranded-resource probes, powered-idle time, p95 wait and p95 turnaround. Memory
conversion, bandwidth, sleep and wake behavior remain explicit model assumptions.
